# Character sprite annotations

The nine supplied images are all 1536×1024, but that does not describe their animation layout. For example, player/01 has 18 idle poses, 15 attack-2 poses, and 14 death poses; boss1 has 13 skill poses. Lines drawn over several source images are guides, not reliable frame boundaries.

## Runtime path

1. Load the original PNG and its adjacent `.png.sprites` file. Check dimensions and SHA-256.
2. For gg and boss1–3 only, repair the exact `0x87ffffff` guide-line overlay from neighbouring pixels. White ice/sword pixels are not colour-keyed out. Suppress alpha ≤16 background haze and tiny isolated noise.
3. Find low-opacity separators within separately annotated row bands and between each pair of pose pivots. Separators can curve around clothing and weapons. Explicit manual paths/masks resolve reviewed exceptions.
4. Extract each pose into its own image with two transparent pixels of padding. The bounding rectangles may overlap, but source-pixel ownership masks do not.
5. Draw around the annotated foot pivot with one scale per character, preserving aspect ratio. Do not scale each tight crop to the collision box. Mirror around the same pivot.
6. Cache the atlas once per source. Map selected poses to the existing 8-tick locomotion / 16-tick combat clocks. These numbers describe playback timing, not source columns.

Visual body heights use 85% of the existing draw height, retaining `gg < player < summon < boss`. Monster rendering now uses the same position origin as its collision box, without the previous -28 px offset. Damage, hit windows, cooldowns, evolution costs, boss progression and dungeon controls are unchanged.

## Annotation format

- `size`: expected source width and height.
- `sha256`: expected source bytes, to reject stale annotations.
- `bodyHeight`: reference upright body height in source pixels; constant across this character's poses.
- `bands`: nine independently measured row-boundary guides. The seven internal paths may move up to 12 px to avoid artwork.
- `row.N`: ordered `x:y` foot pivots, one per actual source pose. Lists can have different lengths.
- `play.N`: optional zero-based source pose sequence. Repeated indices can hold a pose; unspecified rows use all their poses.
- `guides`: optional spacing of the known burned-in overlay. This is only used to remove that overlay, never to locate sprites.
- `cut.ROW.BOUNDARY`: optional source-space `x:y` polyline overriding a separator. Boundary 1 separates source poses 0 and 1.
- `exclude.ROW.POSE`: optional source-space polygon masking an explicitly identified piece of neighbouring artwork.
- `keep.ROW.POSE=main`: retain the largest connected component for an explicitly reviewed disconnected-fragment case. Not applied indiscriminately to weapons or particles.

Original images are never modified. Extraction masks remove pixels; they do not invent missing artwork.

## Limitations already present in the source

Some source effects are painted across neighbouring poses. There is no lossless way to recover the obscured layers from a flattened PNG. These cases are kept visible in Source poses mode for review; ambiguous poses are excluded from gameplay. Orange `[source]` also identifies unused alternate directions, so it does not always mean damaged artwork.

- **01 skill:** pose 5 shares its upper blue effect with pose 4; it is not played. Back-facing locomotion poses are not included in the right-facing movement loop.
- **Evo1 attack1:** poses 8–12 have interleaved green arcs/weapons. Gameplay uses the independent windup, slash, and recovery poses. Attack2 pose 9 and skill poses 9–10 are also omitted.
- **Evo2 attack1:** a manual separator recovers the raised sword tip from pose 3. Poses 10 and 12 are not played. Attack2 poses 7–8 have a slash over a neighbouring head and are omitted.
- **Evo2 skill:** poses 9–11 contain interleaved beams. Pose 12 keeps the complete character and dragon, with the previous pose's red arc masked out. It plays during the unchanged damage window, ticks 11–15. Pose 13 remains available in the source audit; the game returns to idle after the skill.
- **Boss2 skill:** the middle ice wall is continuous between poses. Only independent poses are selected in its annotated playback sequence. Boss2 currently uses attack1/attack2, not this skill row.

Perfect recovery of these excluded effects would require separated source layers or newly drawn frames, not a different crop size. No sprites were redrawn in this change.

## Verification / replacing an image

Run the audit and regression commands in the main README. They check the 72 row counts, every non-empty crop, transparent padding, source bounds, exclusive source-pixel ownership, absence of guide-line pixels, valid playback indices, cache reuse, and left/right rendering geometry. Regression checks also cover missing/stale assets, the three forms' attack/skill hit windows, and X dungeon entry/exit with boss HP reset.

Inspect both `*-contact.png` and `*-boundaries.png`; programmatic ownership checks cannot determine which overlapping effect an artist intended to belong to which pose. `frames.csv` records source bounds and pivots for reuse.

When replacing a PNG, inspect its actual poses, revise only its own `.sprites` annotation, update its hash and the expected audit counts, then regenerate and visually inspect the audit. Do not simply change the hash to silence the source-change error. The `artifacts/sprite-audit` folder is generated review output, not a runtime dependency.
